## 功能进展

### 2026-10-03 - 公众号会话检查与空闲扫码恢复

- 摘要：新增每小时会话检查、等待登录时每15秒检查恢复、持久化告警回执与最近检查时间；扫码操作与发表共用串行锁。
- 影响：没有发布任务时也能发现会话失效、更新扫码结果；登录过期保留已有草稿等待恢复，避免耗尽发布重试次数。
- 结论：健康检查不能承诺永久登录；预防提醒交由 Notify Hub 的4天间隔提醒承载。已手动发表的失败任务不自动续发。
- 验证：全量91项测试通过，修改文件静态检查通过；生产健康接口、控制台北京时间、登录二维码与告警投递通过；发表意图后的认证失效恢复只执行结果核对。

### 2026-10-03 - 数据库迁移与告警恢复

- 摘要：启动执行 Alembic，旧 create_all 数据库验证初始结构后登记基线并升级；登录告警失败使用同一事件键重试，成功回执落库。

## Debug / 复盘

### 2026-10-03 - API 草稿成功但浏览器自动发表失败

- 现象：两次任务均生成正确草稿，浏览器阶段报 DRAFT_OPEN_FAILED，第二次重试另报导航超时；控制台仍显示 ready。
- 结论：旧检测把公众号 `/cgi-bin/` URL 当作登录成功。现场复现发现过期页面可保持原 URL 并返回 HTTP 200，但正文已显示登录超时；旧草稿列表 token 也可能失效。现场证据强烈支持认证失效导致错误归类，但缺少两次失败瞬间快照，不能断言导航超时的唯一原因。
- 处理：识别登录提示与账号 DOM，进入草稿列表前访问首页更新 token；失效转为等待登录，网络超时独立记录；错误信息中的 URL 凭据脱敏。控制台刷新二维码时重新访问登录页，避免返回过期二维码。
- 验证：旧 URL 过期页面与 token 更新回归测试通过；生产实际识别 auth_required，二维码告警成功送达；任务表全部行快照在部署前后相同，两篇历史失败任务没有被重试。
